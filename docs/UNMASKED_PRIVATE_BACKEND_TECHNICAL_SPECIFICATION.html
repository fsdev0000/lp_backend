Core Architecture Principle:
The backend is the single source of truth for investment-based routing. The frontend consumes the backend response to determine the appropriate outcome page and must not implement routing rules independently.
The frontend will consume the defined backend responses to handle loading, validation errors, duplicate submissions, submission failures, and conditional redirects.

1.3 Confirmed MVP Functional Requirements

  • Secure application submission: HTTPS transport, server-side validation, and appropriate application security controls.
  • Storage of all submitted fields: Persistent database record preserving all form inputs across the 3 steps.
  • Duplicate-submission prevention: Preventing repeated identical submissions.
  • Applicant confirmation email: Automated message to the applicant upon submission.
  • Internal notification for Lionel: Direct notification when an applicant qualifies for review.
  • Consent logging: Explicit logging of user agreement to terms and data processing.
  • Privacy Policy version logging: Recording the specific version of the Privacy Policy accepted.
  • Source and UTM tracking: Capturing incoming marketing parameters (campaign, source, referrer).
  • Application-status management: Tracking each submission through its lifecycle.
  • Conditional routing based on investment readiness: Enforcing destination logic by investment bracket.

2. Proposed Technical Solution Technical Proposal

The backend handles application intake, validation, compliance recording, routing evaluation, and notification triggering in a single transactional pipeline:

1. Validate Payload → 2. Check Duplicate → 3. Store Application → 4. Evaluate Investment → 5. Assign Status → 6. Execute Emails → 7. Return Outcome
Proposed MVP Submission Approach:
The application will be submitted to the backend as a single final payload after the applicant completes Step 3. Intermediate step state remains client-side unless Lionel requires abandoned or in-progress applications to be persisted.

2. Success Response: Qualified Review (AED 10,000+ or Value-Dependent)

HTTP 200 OK — Backend returns the qualified-review outcome:

{
  "success": true,
  "outcome": "PENDING_PERSONAL_REVIEW",
  "redirectUrl": "/unmasked-private/thank-you",
  "applicationId": "unm_app_9f82d1c4",
  "referenceNumber": "UNM-2026-6418"
}

3. Success Response: Below Investment Threshold (< AED 10,000)

HTTP 200 OK — Backend returns the below-threshold outcome:

{
  "success": true,
  "outcome": "BELOW_INVESTMENT_THRESHOLD",
  "redirectUrl": "/unmasked-private/not-ready-yet",
  "applicationId": "unm_app_8b11c9e2",
  "referenceNumber": "UNM-2026-6419"
}

4. Error Response: Client Validation Error

HTTP 400 Bad Request — Allows frontend to highlight specific invalid inputs:

{
  "success": false,
  "error": "VALIDATION_ERROR",
  "message": "Please correct the highlighted fields.",
  "fields": {
    "step1.email": "A valid corporate email address is required.",
    "step3.investmentReadiness": "Please select an investment readiness option."
  }
}

5. Error Response: Duplicate Submission

HTTP 409 Conflict — Frontend displays helpful duplicate notice:

{
  "success": false,
  "error": "DUPLICATE_SUBMISSION",
  "message": "An application with this email has already been received and is currently under review."
}

6. Error Response: Server Error

HTTP 500 Internal Server Error — Frontend presents graceful retry state:

{
  "success": false,
  "error": "SUBMISSION_ERROR",
  "message": "We could not process your application at this moment. Please try again."
}

enum UnmaskedApplicationStatus {
  BELOW_INVESTMENT_THRESHOLD

model UnmaskedPrivateApplication {
  id                    String                    @id @default(uuid())
  referenceNumber       String                    @unique // Format: UNM-2026-XXXX
  status                UnmaskedApplicationStatus @default(PENDING_PERSONAL_REVIEW)

  // Step 1: Profile (Provisional structure)
  fullName              String
  email                 String                    @db.VarChar(255)
  phone                 String?
  companyName           String?
  roleTitle             String?

  // Step 2: Context Responses (Flexible storage pending final field lock)
  contextResponses      Json?

  // Step 3: Investment Readiness (Single Source of Truth)

  // Compliance & Consent
  privacyConsentGiven   Boolean                   @default(false)
  privacyConsentDate    DateTime?
  privacyPolicyVersion  String                    @default("v1.0")

  // Attribution & Marketing Tracking
  utmSource             String?
  utmMedium             String?
  utmCampaign           String?
  utmTerm               String?
  utmContent            String?
  referrerUrl           String?

  createdAt             DateTime                  @default(now())
  updatedAt             DateTime                  @updatedAt

  @@index([email])
  @@index([status])
  @@index([createdAt])
}
